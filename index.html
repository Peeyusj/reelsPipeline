SHEET 01

The Line

A typed script becomes a rendered Short through three subprocess stages — voice, captions, stitch — plus one optional side-step that can never fail the render: a like-and-follow prompt painted by a headless browser. A second, optional line plans and paints AI scene images in parallel, then hands the result back in as just another sticker — the render stage never learns it came from an LLM.

Script

+
Plain text, usually Hinglish — Reddit/AITA stories, dark-fact hooks, "did you know" openers. [excited]...[/excited], [sad], and [calm] tags can be inlined; they're stripped before narration and only nudge rate/pitch for that stretch, never spoken aloud.

Voice

+
All four sources emit the exact same shape: audio.mp3 plus a timestamps.json listing every word's start/end in seconds. edge-tts streams Microsoft's free "Read Aloud" voices and gets word timing free from the stream itself; it retries a flaky stream three times and, if Microsoft has rotated its login token (it has), names the exact upgrade that fixes it instead of a cryptic "no audio". Kokoro-82M does the identical job on your CPU, no network call at all. Parler is the one that needs real horsepower — a heavier, more expressive model only a Colab GPU can run. Recorded skips synthesis altogether: your mic take is auto-trimmed, loudness-matched, and transcribed by Whisper for the same per-word timing — and the transcript stays editable, with corrections re-mapped onto the original timings rather than re-transcribed.

Captions

+
Groups words into short lines (2–7 words, your choice) breaking at natural pauses rather than a fixed count, then writes a styled .ass subtitle file. There are seventeen style presets (clean sans through horror and retro-VHS), four sizes, three positions, and seven word-highlight animations — a colour sweep by default, plus pop, shake, glow, bounce and a typewriter reveal. Size is independent of style, and on a full-frame video with no gameplay clip it defaults to extra large because nothing else shares the screen. Flip captions off and this stage doesn't just hide its output, it never runs.

CTA prompt

+
An optional 2–4 second "like & follow" animation, on by default and never mandatory — eight styles, from a finger tapping a Subscribe button to a comic burst or a "loading Part 2" bar stuck at 99%. It is drawn by headless Chrome, not ffmpeg: every frame is a pure function of time, screenshotted onto a transparent background and cached as a PNG sequence, so stitch only has to overlay it — before the captions, which stay on top. When it appears and where it sits are chosen for you (about 60% in, at a pause between sentences, clear of the captions). It can never fail a render: no Chrome, a too-short video, a landscape canvas — the prompt is skipped with a log line and everything else renders as before.

Newest stage: verified by static checks and a stitch dry-run; its first full end-to-end render is still to be confirmed.

Inlets

+
Every optional layer funnels in right before assembly: uploaded stickers, an attached sound effect per sticker, a background music bed, a video intro/outro clip, and — if the AI-image branch ran — finished PNGs. By this point they're all just filenames in one folder; nothing downstream knows or cares where an image came from.

Stitch

+
The only stage that touches ffmpeg. Cover-crops the gameplay clip (or drops it for full-screen mode), stacks it under the caption band, overlays every sticker with its own slide-in or Ken Burns zoom, crossfades between AI images, overlays the like/follow prompt if there is one, burns captions on last, then mixes narration/music/SFX (the prompt's own sound included) — no sidechain ducking, just a deliberately low static bed volume.

Groq

+
One hosted LLM call plans the entire AI-image batch: how many images, what each shows, and a short verbatim quote of where it begins — that quote is then matched against the real measured transcript, so timing comes from the actual audio, not the model's arithmetic.

Image providers

+
Cloudflare Workers AI first (fast, up to four images in parallel, ~95 free images/day per account on the default FLUX.2 klein-4b model), Pollinations next (no signup, no cap, slower per image), your own Colab GPU running FLUX.2 last. Any one of the three can also be picked directly instead of the automatic chain, per batch — and an opt-in HQ Cloudflare entry (FLUX.2 klein-9b, ~7 free images/day) exists for small batches, deliberately kept out of the automatic chain.

Failure handling

+
Accounts: Cloudflare can run on up to five free accounts at once. Requests go round-robin; an account that hits a per-minute 429 sits out about 30 seconds and rejoins, one that spends its day sits out an hour, and if every account is cooling off the call waits for the soonest rather than failing. Only when all are spent does the chain move on to Pollinations.

Safety filter: Cloudflare sometimes flags harmless scenes, so a flagged image is re-seeded up to three times, then handed to the next provider for that one image — without demoting Cloudflare for the rest of the batch.

Partial batches: every image that did render is kept, and the slots that didn't are listed with their time windows — left empty by default so you can drop in your own picture, or covered with repeats if you tick the box.

Output

+
final.mp4, encoded once at 30fps / CRF 20, in either 1080×1920 (Shorts) or 1920×1080 (landscape). Nothing about assembly changes between the two shapes — the frame size is just a number passed down the same pipe.
SHEET 02

Supply Lines

Three different flavors of free feed this pipeline. All of them read $0 on the gauge. None of them behave the same way once you actually turn the tap.

01 · LOCAL

Your machine

edge-tts · Kokoro-82M (CPU) · ffmpeg · headless Chrome (the like/follow prompt) — all run on your own laptop. Kokoro and ffmpeg never touch the network; edge-tts only calls Microsoft's free endpoint.
LIMITnone — click for detail
Kokoro-82M is Apache-2.0 licensed and runs CPU-only — no GPU, no API key, no rate limit, ever. edge-tts is an unofficial client of Microsoft's free "Read Aloud" endpoint; the only real risk is Microsoft changing that endpoint underneath it — which has happened once already, so the app now retries and names the fix (upgrade edge-tts).
$0.00 · unlimited runs
02 · BORROWED — GOOGLE COLAB

A temporary GPU

Parler AI voice · FLUX.2 image option, each on its own free T4 GPU, reached over an ngrok or gradio.live tunnel you start by hand.
LIMIT~90 min idle · click for detail
Roughly a 90-minute idle timeout and a ~12-hour hard session cap, with occasional GPU unavailability on the free tier. Fine for personal, attended use; not something to build unattended automation on top of — you open a notebook, copy a URL into PARLER_ENDPOINT or FLUX_ENDPOINT, and it works until the session ends.
$0.00 · you babysit the session
03 · HOSTED FREE-TIER

No infra to run

Cloudflare Workers AI, Pollinations (image generation, no key), and Groq (LLM planning) — a hosted call, nothing to keep open.
LIMIT~95 img/day per account · click for detail
Cloudflare's free tier is 10,000 neurons a day per account — roughly 95 images on the default FLUX.2 klein-4b model, and only about 7 on the pricier klein-9b. Each extra free account (up to five) brings its own allowance, and the pipeline rotates across them automatically. Pollinations has no daily cap but is slower per image and can't hold a saved character's reference. Groq caps at 8,000 tokens/minute on its free model — the pipeline paces its own requests to stay under that automatically.
$0.00 · quota, not a session
No subscriptions, no credit card, no database. The tax on "free" is patience, not money — a Colab session needs a human to start it and can vanish mid-batch. That single risk is exactly why the image pipeline no longer depends on Colab alone: Cloudflare and Pollinations exist specifically so one dead tunnel can't stall an entire batch of images — and why Cloudflare itself can spread across several free accounts, so one spent daily allowance doesn't end its turn either.
SHEET 03

Decision Log

Every kink in this line was put there by something that broke first. Read each row left to right — a starting choice, what it broke, what got built because of it. Click "+ more" on any row for the fuller story.

started here broke like this fixed by building
01
Free & local, always
→
Parler's AI-voice model too big for an 8 GB laptop
→
Borrow a Colab GPU, temporarily
more
Two other free options were tried first: running the model locally (ruled out immediately — it doesn't fit) and Hugging Face's free ZeroGPU tier (ruled out after it moved to a paid plan). Colab's free T4 was the door left open, so the app treats it as a temporary, session-scoped resource rather than pretending it's an always-on service. The tunnel pattern built here was reused, unchanged, for the FLUX image GPU later.
02
Sticker images lived in a server-side library
→
People wanted to place their own images
→
Pivoted to session-only browser uploads
more
The very first version was closer to a stock-photo picker than a personal editor — everyone chose from the same shared set. The moment real usage showed people wanted to upload their own reaction images, the whole flow had to move from a JSON body to multipart form data, since JSON can't carry binary files. That format decision has held for every upload added since: video clips, character references, all of it.
03
LLM asked to guess each image's timestamp directly
→
Guesses drifted off the real narration on longer scripts
→
Phrase-anchoring: LLM quotes the script, code finds the real time
more
The original scheme asked for start_ms/end_ms in the same response as the image prompt — asking a language model to do arithmetic it has no way to check. It can guess what a scene should show, but not how many seconds a sentence takes to actually say. The fix throws that guess away and instead asks for a short verbatim quote of where a scene begins, then matches that quote against the real, measured per-word transcript the captions already use.
04
One Colab GPU was the only free image backend
→
One dead tunnel could stall an entire batch
→
Added Cloudflare + Pollinations, tried in automatic order
more
Before this, "the AI-image feature" and "my Colab session" were the same fragile thing. Cloudflare and Pollinations were added specifically because neither needs a browser tab open anywhere — a batch that starts on Cloudflare and hits its daily quota simply continues on Pollinations without anyone noticing. The provider abstraction meant this cost one class per backend, zero pipeline changes.
05
Image ceiling raised 60 → 100 per batch
→
Groq's free model burned its whole budget "thinking," returned nothing
→
Chunked requests + a rolling token-budget pacer
→
The assembled ffmpeg command passed Windows' 32,767-char limit
→
Filter graph now offloads to a file above that threshold
more
Raising a limit usually looks like the cheapest change in a codebase — one integer. This one quietly assumed every downstream system could handle 100 of something that used to top out at 60: a free LLM's per-minute token budget, and a decades-old Windows limit on how long a command line is allowed to be. Both had been fine at 60 and both broke at 100 — the fixes are now permanent, not one-off patches.
06
A reference image pinned the character's pose, not just its look
→
A whole batch became "sitting at a desk," five times over
→
Prompt now explicitly demands a different shot per image
more
Reference-image conditioning is supposed to fix appearance — face, clothes, colors. What it also does, unless told otherwise, is anchor the pose and camera angle the reference photo happened to be shot at. Every image in a batch inherited the same framing until the prompt was rewritten to explicitly demand a different shot — angle, pose, location — each time.
07
Render jobs lived only in memory
→
A server restart erased every finished video's settings
→
project.json now survives to disk, with a bounded 10-job retention
more
Every render job before this lived only in the server's memory — restart the backend, even a routine code-reload, and every finished video's settings vanished, even though the .mp4 was still sitting right there on disk. Now a finished job's settings, audio, and stickers are durable, with the oldest past the 10th quietly cleaned up — the first cleanup rule ever applied to render output.
08
Every narration was synthetic — edge, Kokoro, or Parler
→
No way to use your own voice, ad-libs, or delivery
→
Recording plugs into the exact same audio.mp3 + timestamps.json contract
more
Nothing past the voice stage cares HOW audio.mp3 and timestamps.json were made — captions, word-pop animation, the timeline, AI-image pacing all just read those two files. So "record it yourself" needed no new pipeline: a mic take is uploaded, auto-trimmed of dead air, loudness-normalized to sit at the same level TTS narration does, and transcribed word-by-word by Whisper (Groq's free tier by default, or fully offline). A misheard word can still be corrected in the transcript — the fix is diffed against the original recognition and the OLD timing is kept for every word that didn't change, so a one-word correction doesn't reshuffle the whole caption track.
09
Cloudflare's free allowance is one fixed pot per account
→
A big batch drained the day's pot, and bursts tripped per-minute 429s
→
Rotate across up to five free accounts, benching each only as long as it needs
more
Every Cloudflare account carries its own 10,000 neurons a day, so a second and third free account multiply the budget instead of sharing it. Extra accounts are optional env-var pairs (CLOUDFLARE_ACCOUNT_ID_2 / CLOUDFLARE_API_TOKEN_2, up to _5); with just one, nothing changes. Requests go round-robin across the healthy accounts. A 429 benches only that account for about 30 seconds (or the server's own Retry-After) and it rejoins; a spent-day error benches it for an hour. If every account is cooling off, the call waits up to 90 seconds for the soonest one rather than raising. Only when all of them are spent does Cloudflare give up and let the chain fall through to Pollinations. The whole thing lives inside the one Cloudflare provider class — nothing above it knows more than one account exists.
10
Cloudflare's safety filter judges the finished image, not the prompt
→
Harmless scenes got flagged, and one flag demoted the provider for the whole batch
→
Re-seed up to three times, then hand only that image onward
more
A cartoon fox in an office was flagged about 60% of the time in testing — enough to cut a five-image batch down to one. Because the check runs on the output, retrying the same seed is pointless but a different seed usually passes, so a flagged image is re-seeded up to three times. If it still fails, the refusal is raised as "this one request was rejected" rather than "this provider is down": the next provider draws just that image, and Cloudflare stays first in line. Treating a flag as an outage used to quietly move the rest of the batch onto a backend that ignores the character reference, so the character changed mid-video; the chain now also prints a loud warning whenever a backend ignored the reference.
11
A batch kept only the images before its first failure
→
One 429 on image 4 threw away perfectly good images 5–12
→
Keep everything that rendered; list the empty slots, with times, for you to fill
more
The old assembly step trimmed the result to the unbroken run of successes and deleted every image after the first gap. Now every rendered image is kept and the failed slots travel with the job as a "missing" list — scene number, time window, what it was meant to show, and why it failed — which the UI prints as, say, "Scene 4 — 0:12–0:20". A checkbox, off by default, picks what happens to those holes: leave them empty so you can drop in your own picture, or cover them with repeats of images that worked, capped so no single frame holds the screen longer than 20 seconds.
12
A like/follow nudge needs to look like real app UI
→
ffmpeg can't draw it, and a render that can run over an hour must not be risked on a garnish
→
Headless Chrome paints transparent frames; stitch overlays them; any failure just skips it
more
Each of the eight prompts is a pure function of time, so frame i is just "draw at i/30 seconds" — output is exact, repeatable, and the browser preview can't drift from the rendered clip. Frames are cached under a fingerprint that includes the design files themselves, so editing a design never reuses stale frames; a style costs about ten seconds of Chrome the first time and is free after. Start time and position are chosen automatically (roughly 60% in, at a sentence pause, clear of the captions and the app's own like/comment rail), and vertical 9:16 only — landscape renders skip it. The same philosophy as the outro card: optional, additive, and never able to take the render down with it.
13
edge-tts is an unofficial client of Microsoft's Read Aloud endpoint
→
Microsoft rotated its login token; valid scripts began failing with "no audio"
→
Retry with backoff, then an error that names the exact upgrade
more
The failure was maddening because nothing about the script, voice or speed was wrong — the library itself had gone stale, and only a newer edge-tts (7.3.0 or later) can speak the new token. Each segment now gets three attempts with a growing delay, and if they all fail the error says which edge-tts version it found, what to run to upgrade it, and that a Kokoro voice works offline in the meantime. The message is kept plain ASCII with the token-bearing URL stripped out, because it travels through a Windows pipe to the UI.
