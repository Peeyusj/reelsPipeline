SHEET 01

The Line

A typed script becomes a rendered Short through three subprocess stages, no more. A second, optional line plans and paints AI scene images in parallel, then hands the result back in as just another sticker — the render stage never learns it came from an LLM.

hover any part of the diagram for a one-line note — the cards below go deeper
click a part to read what it actually does

Script

+
Plain text, usually Hinglish — Reddit/AITA stories, dark-fact hooks, "did you know" openers. [excited]...[/excited], [sad], and [calm] tags can be inlined; they're stripped before narration and only nudge rate/pitch for that stretch, never spoken aloud.

Voice

+
All three engines emit the exact same shape: audio.mp3 plus a timestamps.json listing every word's start/end in seconds. edge-tts streams Microsoft's free "Read Aloud" voices and gets word timing free from the stream itself. Kokoro-82M does the identical job on your CPU, no network call at all. Parler is the one that needs real horsepower — a heavier, more expressive model only a Colab GPU can run.

Captions

+
Groups words into short lines (2–7 words, your choice) breaking at natural pauses rather than a fixed count, then writes a styled .ass subtitle file — position, font, word-highlight animation all configurable. Flip captions off and this stage doesn't just hide its output, it never runs.

Inlets

+
Every optional layer funnels in right before assembly: uploaded stickers, an attached sound effect per sticker, a background music bed, a video intro/outro clip, and — if the AI-image branch ran — finished PNGs. By this point they're all just filenames in one folder; nothing downstream knows or cares where an image came from.

Stitch

+
The only stage that touches ffmpeg. Cover-crops the gameplay clip (or drops it for full-screen mode), stacks it under the caption band, overlays every sticker with its own slide-in or Ken Burns zoom, crossfades between AI images, burns captions on last, then mixes narration/music/SFX — no sidechain ducking, just a deliberately low static bed volume.

Groq

+
One hosted LLM call plans the entire AI-image batch: how many images, what each shows, and a short verbatim quote of where it begins — that quote is then matched against the real measured transcript, so timing comes from the actual audio, not the model's arithmetic.

Image providers

+
Cloudflare Workers AI first (fast, ~95 free images/day), Pollinations next (no signup, no cap, slower per image), your own Colab GPU running FLUX.2 last. Any one of the three can also be picked directly instead of the automatic chain, per batch.

Output

+
final.mp4, encoded once at 30fps / CRF 20, in either 1080×1920 (Shorts) or 1920×1080 (landscape). Nothing about assembly changes between the two shapes — the frame size is just a number passed down the same pipe.
SHEET 02

Supply Lines

Three different flavors of free feed this pipeline. All of them read $0 on the gauge. None of them behave the same way once you actually turn the tap.

01 · LOCAL

Your machine

edge-tts · Kokoro-82M (CPU) · ffmpeg — runs entirely on your own laptop, no network call for two of the three voices, and none at all for assembly.
LIMITnone — click for detail
Kokoro-82M is Apache-2.0 licensed and runs CPU-only — no GPU, no API key, no rate limit, ever. edge-tts is an unofficial client of Microsoft's free "Read Aloud" endpoint; the only real risk is Microsoft changing that endpoint underneath it.
$0.00 · unlimited runs
02 · BORROWED — GOOGLE COLAB

A temporary GPU

Parler AI voice · FLUX.2 image option, each on its own free T4 GPU, reached over an ngrok or gradio.live tunnel you start by hand.
LIMIT~90 min idle · click for detail
Roughly a 90-minute idle timeout and a ~12-hour hard session cap, with occasional GPU unavailability on the free tier. Fine for personal, attended use; not something to build unattended automation on top of — you open a notebook, copy a URL into PARLER_ENDPOINT or FLUX_ENDPOINT, and it works until the session ends.
$0.00 · you babysit the session
03 · HOSTED FREE-TIER

No infra to run

Cloudflare Workers AI, Pollinations (image generation, no key), and Groq (LLM planning) — a hosted call, nothing to keep open.
LIMIT~95 img/day · click for detail
Cloudflare's free tier gives roughly 95 images/day on the higher-quality model. Pollinations has no daily cap but is slower per image and can't hold a saved character's reference. Groq caps at 8,000 tokens/minute on its free model — the pipeline paces its own requests to stay under that automatically.
$0.00 · quota, not a session
No subscriptions, no credit card, no database. The tax on "free" is patience, not money — a Colab session needs a human to start it and can vanish mid-batch. That single risk is exactly why the image pipeline no longer depends on Colab alone: Cloudflare and Pollinations exist specifically so one dead tunnel can't stall an entire batch of images.
SHEET 03

Decision Log

Every kink in this line was put there by something that broke first. Read each row left to right — a starting choice, what it broke, what got built because of it. Click "+ more" on any row for the fuller story.

started here broke like this fixed by building
01
Free & local, always
→
Parler's AI-voice model too big for an 8 GB laptop
→
Borrow a Colab GPU, temporarily
more
Two other free options were tried first: running the model locally (ruled out immediately — it doesn't fit) and Hugging Face's free ZeroGPU tier (ruled out after it moved to a paid plan). Colab's free T4 was the door left open, so the app treats it as a temporary, session-scoped resource rather than pretending it's an always-on service. The tunnel pattern built here was reused, unchanged, for the FLUX image GPU later.
02
Sticker images lived in a server-side library
→
People wanted to place their own images
→
Pivoted to session-only browser uploads
more
The very first version was closer to a stock-photo picker than a personal editor — everyone chose from the same shared set. The moment real usage showed people wanted to upload their own reaction images, the whole flow had to move from a JSON body to multipart form data, since JSON can't carry binary files. That format decision has held for every upload added since: video clips, character references, all of it.
03
LLM asked to guess each image's timestamp directly
→
Guesses drifted off the real narration on longer scripts
→
Phrase-anchoring: LLM quotes the script, code finds the real time
more
The original scheme asked for start_ms/end_ms in the same response as the image prompt — asking a language model to do arithmetic it has no way to check. It can guess what a scene should show, but not how many seconds a sentence takes to actually say. The fix throws that guess away and instead asks for a short verbatim quote of where a scene begins, then matches that quote against the real, measured per-word transcript the captions already use.
04
One Colab GPU was the only free image backend
→
One dead tunnel could stall an entire batch
→
Added Cloudflare + Pollinations, tried in automatic order
more
Before this, "the AI-image feature" and "my Colab session" were the same fragile thing. Cloudflare and Pollinations were added specifically because neither needs a browser tab open anywhere — a batch that starts on Cloudflare and hits its daily quota simply continues on Pollinations without anyone noticing. The provider abstraction meant this cost one class per backend, zero pipeline changes.
05
Image ceiling raised 60 → 100 per batch
→
Groq's free model burned its whole budget "thinking," returned nothing
→
Chunked requests + a rolling token-budget pacer
→
The assembled ffmpeg command passed Windows' 32,767-char limit
→
Filter graph now offloads to a file above that threshold
more
Raising a limit usually looks like the cheapest change in a codebase — one integer. This one quietly assumed every downstream system could handle 100 of something that used to top out at 60: a free LLM's per-minute token budget, and a decades-old Windows limit on how long a command line is allowed to be. Both had been fine at 60 and both broke at 100 — the fixes are now permanent, not one-off patches.
06
A reference image pinned the character's pose, not just its look
→
A whole batch became "sitting at a desk," five times over
→
Prompt now explicitly demands a different shot per image
more
Reference-image conditioning is supposed to fix appearance — face, clothes, colors. What it also does, unless told otherwise, is anchor the pose and camera angle the reference photo happened to be shot at. Every image in a batch inherited the same framing until the prompt was rewritten to explicitly demand a different shot — angle, pose, location — each time.
07
Render jobs lived only in memory
→
A server restart erased every finished video's settings
→
project.json now survives to disk, with a bounded 10-job retention
more
Every render job before this lived only in the server's memory — restart the backend, even a routine code-reload, and every finished video's settings vanished, even though the .mp4 was still sitting right there on disk. Now a finished job's settings, audio, and stickers are durable, with the oldest past the 10th quietly cleaned up — the first cleanup rule ever applied to render output.
